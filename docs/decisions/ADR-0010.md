# 10. Ingest topology: frames in, one fusion process, demodulation outside the decoders

* Status: Accepted
* Date: 2026-11-04
* Deciders: Colin Wolff
* Related: `ADR-0003`, `ADR-0004`, `ADR-0009`, `docs/SPEC.md` Invariant 10, `docs/ARCHITECTURE.md` §3

## Context and Problem Statement

The normal deployment is two dongles: one on 1090 MHz, one on 978 MHz, each with its own demodulator.
Fusion — ADS-R deduplication, "direct reception beats re-broadcast", one authoritative position per
aircraft — needs both bands inside one track table (`SPEC.md` Invariant 10). So the topology is not
free: get it wrong and the tracker silently stops doing the job it exists for.

Three things were unresolved:

1. Nothing in the docs described an ingest *source model*: how many sources a process accepts, how
   each is tagged, or that one process fuses them.
2. `README.md` and `PROJECT.md` claimed the decoder crates demodulate, while `ROADMAP.md` never
   scheduled a demodulator — a promise with no owner.
3. `aerofoil-cli` is single-`stdin` by construction, so two-feed fusion is server-only. True, but
   unstated, and a dual-dongle user's first instinct is two CLI invocations, which loses dedup.

The volumes decide most of it. I/Q at ~2.4 Msps × 8-bit is roughly **4.8 MB/s per dongle**; frames at
high aircraft density are roughly **28 KB/s**. A boundary at frames is ~200× cheaper than one at
samples, and µs of IPC against updates measured in hundreds of ms is noise.

There is also a stronger reason than cost: **Beast already exists as the seam.** `aerofoil-server`
ingests Beast on 30005/30978, `aerofoil-cli` reads AVR/Beast on stdin, and `SPEC.md` §5 specifies the
Beast frame including its MLAT timestamp. A demodulator emitting Beast is indistinguishable from
dump1090 to everything downstream — so it can be a drop-in replacement with **zero new integration**.

## Considered Options

1. **Demodulation inside the decoder crates.** One binary, no seam. Rejected: it drags DSP, threads
   and an optional C library into crates that must stay `#[no_std]` and allocation-free
   (`AGENTS.md` §3.1), and makes the decoders untestable without hardware.
2. **A sibling `aerofoil-sdr` crate emitting Beast** (chosen). Device and DSP stay out of the
   decode graph, the seam is a documented stream format, and the crate is usable on its own.
3. **Require an external dump1090/dump978.** Zero work. Rejected: forfeits the suite's own
   demodulator and any control over its quality, and the project explicitly wants the drop-in.
4. **`aerofoil-sdr` as a library linked into `aerofoil-server`.** One process, no serialisation.
   Rejected: destroys the drop-in property (nobody can pipe it into readsb), couples DSP releases to
   server releases, and puts USB/DSP faults on the daemon's error path.

## Decision Outcome

Chosen: **option 2** — an `aerofoil-sdr` crate, feature-gated as `dsp` (pure functions over
`&[Complex<u8>]`, testable from recorded I/Q) and `device` (USB, tuning, gain, PPM correction, behind
a feature so CI needs no `librtlsdr`). It emits Beast on stdout and/or a TCP port. Ingest is therefore
**N band-tagged sources fused in one process**; the CLI stays single-stream and says so.

### The three boundaries, resolved by the Unix-philosophy test

`README.md` already states the principle that settles the hard one: *"Decoupled Mechanisms from
Policies: decoders parse frames into strict data types; correlation, persistence and network
distribution are independent layers."*

1. **No correction in `aerofoil-sdr`; validation only.** CRC-24/RS validation is a *mechanism* — on
   both bands you cannot even find a frame in noise without it, so it stays in the demodulator.
   Correction is a *policy*: it consults an address set to avoid phantom aircraft (`ADR-0003`,
   `ADR-0004`), and `-sdr` holds no state. Beast also cannot express "this frame was repaired", so a
   correcting demodulator would silently launder uncertainty — against `SPEC.md` §6's no-silent-repair
   rule. `aerofoil-1090` therefore remains the only place correction happens, for every input source.
2. **Zero workspace dependency; raw Beast bytes.** A tool that depends on our Rust types cannot be
   piped into readsb, so it fails the drop-in requirement and the "each crate is useful on its own"
   rule (`AGENTS.md` §2). `aerofoil-sdr | aerofoil-cli` must work, and so must
   `aerofoil-sdr | nc some-other-consumer 30005`.
3. **Uplink demodulation deferred.** UAT uplink reception needs the ground station's transmission
   schedule, which is a scheduling problem, not a demodulation one — one thing well. The *parser*
   keeps `RS(92, 72)` so uplink frames supplied by a file or another tool still decode
   (`SPEC.md` Invariant 7). Recorded as deferred, not decided against.

### Consequences for work already planned

* `aerofoil-1090`'s CRC-24 work (M2) narrows in role but does not shrink: it remains the path for
  third-party input (dump1090, readsb, recorded captures) and it is the only correction site.
* The recording format in `AF-24` must carry band and source, because that is now the shape of every
  real deployment.
* `aerofoil-sdr` and `aerofoil-persistence` are not among the eight reserved crate names; both need a
  reservation run before they can publish.

### Evidence still required (a ticket to be created, not a vibe)

A **DSP feasibility spike**: can two bands be demodulated concurrently on Pi-class hardware at
~2.4 Msps each, and what does magnitude, preamble correlation and PPM slicing cost per sample? The
seam above is a design argument and stands either way; the viability of the `device` module on the
target hardware is a measurement.

### Positive Consequences

* The tracker sees both bands, so deduplication works by construction rather than by deployment luck.
* A dump1090 replacement is additive: it plugs into a port that is already specified and tested.
* Decoders stay `no_std`, allocation-free and hardware-free to test.

### Negative Consequences

* Two processes to run instead of one, and a stream format to keep honest.
* Frames arriving from `-sdr` are already validated, so a decoder cannot distinguish "clean" from
  "validated elsewhere" except by re-checking — which it does anyway.
* The CLI cannot fuse; anyone wanting dedup must run the server. Documented, not prevented.
