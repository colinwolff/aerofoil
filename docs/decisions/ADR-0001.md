# 1. Use Cargo Virtual Workspace and Zero-Allocation Core Decoders

* Status: Accepted
* Date: 2026-11-04

## Context and Problem Statement
Decoding real-time ADS-B and UAT broadcasts requires handling high throughput (thousands of frames/sec in dense airspace) on constrained devices (Raspberry Pi, microcontrollers, embedded SDR nodes) without CPU starvation or unpredictable latency. How should the project structure core parsing logic across protocols while ensuring maximum performance and composability?

## Considered Options
1. Monolithic crate housing 1090, 978, tracking, and network servers.
2. Virtual workspace separating protocol decoders (`no_std`) from tracking and networking layers.
3. Macro-generated parser based on dynamic AST generation.

## Decision Outcome
Chosen option: **Option 2 (Virtual workspace with zero-allocation `no_std` core decoders)**.

### Positive Consequences
* Core decoders (`aerofoil-1090`, `aerofoil-978`, `aerofoil-common`) can compile in `#![no_std]` environments (microcontrollers, WebAssembly, bare-metal RTOS).
* Strict isolation: Bitfield parsing bugs or changes in 978 UAT do not affect 1090ES tests or dependencies.
* Guarantees zero heap allocations (`malloc`/`free`) on the frame processing hot path.

### Negative Consequences
* Workspace build dependencies and Cargo configuration overhead.
* Conversion traits must be explicitly maintained across crate boundaries.
