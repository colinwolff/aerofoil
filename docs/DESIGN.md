# Low-Level Design Specification: `aerofoil`

## 1. Bit-Level Parsing & Zero-Allocation Primitives

To guarantee zero allocations and predictable execution latency, frames are represented as fixed-size byte wrappers or packed structures.

### Fixed-Size Packet Slices
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct RawFrame1090([u8; 14]);

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct RawUatDownlink([u8; 48]);
```

## 2. Parity & Error Correction Implementations

### 2.1 Mode S CRC-24 Engine (`aerofoil-1090`)
The generator polynomial defined in ICAO Annex 10 is:
$$G(x) = x^{24} + x^{23} + x^{22} + x^{21} + x^{20} + x^{19} + x^{18} + x^{17} + x^{16} + x^{15} + x^{13} + x^{10} + x^8 + x^7 + x^5 + x^3 + x^1 + 1$$
Represented in hex as `0x1FFF409`.

#### Implementation Strategy:
1. **Lookup-Table Approach (Baseline):** A precomputed 256-word table (`[u32; 256]`) processing 8 bits per iteration:
   $$\text{crc} = (\text{crc} \ll 8) \oplus \text{TABLE}[(\text{crc} \gg 16) \oplus \text{byte}]$$
2. **SIMD Carry-less Multiplication (Fast Path):** For x86-64 (`pclmulqdq`) and aarch64 (`pmull`), compute the 24-bit remainder over the 112-bit payload directly in registers without memory lookups.

### 2.2 UAT Reed-Solomon Codec (`aerofoil-978`)
DO-282B specifies Reed-Solomon coding over the Galois Field $GF(2^8)$ generated by the primitive polynomial:
$$P(x) = x^8 + x^4 + x^3 + x^2 + 1 \quad (\text{hex } \mathtt{0x11D})$$

* **Downlink:** $RS(48, 34)$ with parity check polynomial roots at $\alpha^{120}, \alpha^{121}, \dots, \alpha^{133}$.
  * Capable of correcting up to $t = \frac{48 - 34}{2} = 7$ erroneous bytes.
* **Syndrome Generation:**
  $$S_i = \sum_{j=0}^{N-1} r_j (\alpha^i)^j, \quad i \in [120, 133]$$
* **Error Solver:** Branch-free Berlekamp-Massey algorithm to find the error locator polynomial $\Lambda(x)$, followed by Chien search and Forney algorithm for root and magnitude resolution.

## 3. Compact Position Reporting (CPR)

DO-260B CPR compresses high-precision coordinates into 17-bit odd and even frame values.

### Mathematical Formulation
The number of latitude zones $NZ = 60$.
1. **Latitude Resolution:**
   $$\Delta\text{Lat}_{\text{even}} = \frac{360}{60} = 6^\circ, \quad \Delta\text{Lat}_{\text{odd}} = \frac{360}{59} \approx 6.1017^\circ$$
2. **Zone Index Calculation:**
   $$j = \left\lfloor \frac{59 \cdot \text{Lat}_{\text{even}} - 60 \cdot \text{Lat}_{\text{odd}}}{2^{17}} + \frac{1}{2} \right\rfloor$$
3. **Longitude Transition ($NL$ Function):**
   $$NL(\text{lat}) = \left\lfloor 2\pi \cdot \left[ \arccos\left(1 - \frac{1 - \cos(\pi / (2 \cdot NZ))}{\cos^2(\pi \cdot \text{lat} / 180)}\right) \right]^{-1} \right\rfloor$$

To preserve embedded determinism, the $NL(\text{lat})$ transition table is precomputed as a fixed 60-element boundary array indexed by absolute latitude.

## 4. Model Context Protocol (MCP) Server Design

`aerofoil-mcp` exposes high-level aviation tools to external LLM environments over standard I/O (JSON-RPC):

```json
{
  "name": "get_airspace_snapshot",
  "description": "Returns current tracked aircraft within bounding box or radius",
  "inputSchema": {
    "type": "object",
    "properties": {
      "center_lat": { "type": "number" },
      "center_lon": { "type": "number" },
      "radius_nm":  { "type": "number" }
    },
    "required": ["center_lat", "center_lon", "radius_nm"]
  }
}
```
State queries are served non-blocking from the tracker cache without taking coarse-grained table locks.
